# 2026-09-25 — TeSiMok v2 (tebak stiker jomok)

## What was built
Full v2 rewrite of the sticker-guessing game on top of the existing Supabase project
(ref `qwvrcrpshjtvbuitkbrt`, name "tesimok"). Codebase is complete; **DB migration not yet applied**.

## Architecture (3-tier, strict)
`screens → services → Supabase`. No screen calls Supabase directly.

```
src/
  config/game.js        single source of gameplay tuning (lives, keys, scoring, plans, rewards)
  lib/                  dom.js, format.js, audio.js (Web Audio synthesized SFX)
  services/             supabase.js, profile.js, stages.js, battle.js, shop.js, leaderboard.js
  state/                store.js (observable + life ticker), router.js (hash router)
  components/           primitives.js, shell.js
  screens/              auth, home, stages, game, battle, shop, subscription, daily, leaderboard, profile
  styles/               tokens.css, components.css, screens.css
supabase/
  migrations/20260925000001_v2_game_system.sql   ← 13 tables, 16 RPCs, RLS, realtime, seeds
```

## Key design decisions
- **Server-authoritative economy**: every life/key/coin/rating change goes through an RPC,
  never a direct table write.
- **Lazy regen, no cron**: lives refill is computed on read via `FLOOR(elapsed / 7200s)`.
- **Life regen**: max 5 lives, +1 per 2 hours. **Keys**: 2 free/day, pack = Rp20.000 / 5 keys.
- **Difficulty scaling**: `questions` table has no difficulty column, so difficulty is ramped
  using a confusion-score proxy (how often an answer appears as a distractor elsewhere).
- **Mirrored battle arena**: CSS `rotate(180deg)` on opponent half; top/bottom on mobile,
  left/right at ≥720px.
- **Atomic sticker purchase**: `purchase_sticker` RPC with `FOR UPDATE` balance check
  (replaces an earlier non-atomic client read→deduct→insert flow).

## Bugs found & fixed this session
1. `src/screens/home.js` — unused `toast` import removed.
2. **`src/state/router.js` — real routing bug.** Only listened for `popstate`, so changing
   `location.hash` directly (typed URL, `<a href="#/shop">`) left the previous screen mounted
   and the URL and rendered screen desynced. Fixed by adding a `hashchange` listener plus a
   shared `sync()` that skips re-navigating when already on that route and falls back to the
   default route for unknown names.
